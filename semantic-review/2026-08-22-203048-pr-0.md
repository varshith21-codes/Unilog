# Collapsible desktop navigation rail for the AXIOM console

The console shell now lets desktop users reduce the existing 16.5rem sidebar to a 4.5rem icon rail without changing the mobile shell. Collapse state lives in a dedicated client component, leaving `RootLayout` as a server component with its metadata and viewport exports intact. The rail retains all six routes, current-route styling, workspace status, the theme control, and keyboard-visible focus while replacing hidden copy with accessible names and native tooltips. Root-page and desktop-nav scrollbar chrome is suppressed without disabling scrolling or changing the mobile horizontal nav.

Watch for: **confirmed** — no live browser session was run, so breakpoint behavior, native title tooltips, and hidden-scrollbar keyboard interaction were source-reviewed but not interactively exercised.

**Verdict**: APPROVED

## High-level view

`DesktopSidebar` is the only new stateful boundary. It owns non-persistent collapse state and composes the existing navigation and theme controls; `RootLayout` continues to own the metadata, viewport, mobile header, skip link, data banner, and main target.

At 64rem and above, the shell grid sizes its first column from the sidebar’s 16.5rem or 4.5rem tokenized width. The width swap has no transition, so the content column reflows immediately rather than animating layout.

The rail visually removes brand, workspace, route, descriptor, and group copy while retaining equivalent accessible names. Route activity and keyboard focus remain explicit, and the collapse control exposes its target, current state, and available action.

Scrollbar suppression is limited to the root document and the desktop sidebar’s vertical nav. Overflow remains enabled, the desktop nav is keyboard-focusable, and the existing mobile horizontal scrollbar styling is untouched.

## `DesktopSidebar` isolates collapse state from the document shell

The new client component contains the only state introduced by the change and receives the server-rendered product mark as content. This keeps metadata, viewport, the pre-paint theme script, skip link, and `#main` in the server layout while reusing the existing route-aware `Nav` and `ThemeToggle` clients.

```text
RootLayout (server: metadata, viewport, document shell)
├── DesktopSidebar (client: local collapse state)
│   ├── Nav
│   └── ThemeToggle
└── app-content
    ├── mobile header + mobile Nav
    └── #main
```

## Collapsed routes keep names, activity, and focus

The control at `desktop-sidebar.tsx:55-63` targets the sidebar, maps expanded state to `aria-expanded`, switches both its accessible label and tooltip, and uses an inline chevron. In `nav.tsx:79-89`, only collapsed desktop links replace hidden route copy with a combined `aria-label` and `title`; the existing `activeFor` matcher and `aria-current="page"` remain the source of the compact accent state in `globals.css:1460-1475`. Existing global `:focus-visible` styling still covers the button and all route links.

The collapsed CSS centers the product mark, workspace indicator, six route glyphs, and theme control. A separator takes over from the hidden “Analysis” label, so Intelligence remains visually grouped without restoring text. Mobile links receive neither collapsed labels nor the desktop nav focus stop, and the route-change `scrollIntoView` behavior at `nav.tsx:121-126` is unchanged.

## Root and sidebar scrollbars lose chrome, not scrolling

The root scrollbar selectors at `globals.css:284-294` add no `overflow` restriction. The desktop nav retains `overflow-y: auto`, hides only its scrollbar at `globals.css:1394-1409`, and becomes focusable at `nav.tsx:131` for keyboard scrolling. These selectors do not target table wrappers or `.workflow-nav-mobile`, whose existing horizontal overflow and thin scrollbar rules remain active.
